## ① 사실(fact) = As-Is — 알고 있는 사실

- DOROBUS(도로버스)는 초등 고학년~중학생 대상 **Web 3D 학습 플랫폼**이다. DLS 온라인 수업(주 1회)을 이 공간에서 진행한다.
- 플랫폼 내 가상 화폐 **셀(Cell)** 의 획득처는 현재 **수업 · 과제 완료 · 타자게임 1등 · 이벤트** 등으로 한정되어 있다.
- 셀의 소비처는 풍부하다: 마이룸 꾸미기(가구·벽지·스킨·펫), 상점 가챠(장비·펫·스킨) 등.
- **획득처 < 소비처** 구조이며, 기업은 "수업 없는 날에도 아이들이 스스로 접속하는 공간"으로 확장하기를 원한다. (담당자 이현승 팀장: "공작소와 미니게임 부분을 가장 원한다")
- 체험 계정(강사/학생)으로 실제 플랫폼을 탐색하였으며, 마이룸은 3D 공간(Babylon.js), 상점은 가챠 구조임을 확인하였다.
- 주 사용자는 **초등 고학년~중학생**이며, 성인 기준의 UI/콘텐츠는 실패 사례가 된다.

## ② 생각(idea/hypothesis) = To-Be — 가설/해결안

- **가설 1**: 아이가 **직접 만든 존재(루미)** 가 마이룸에 살면, "내 로봇이 나를 기다리고 있다"는 감정이 재접속 동기가 된다.
- **가설 2**: 색칠·커스터마이징 결과를 AI가 성격·대사로 변환하면, "다른 색을 칠하면 다른 성격이 나온다"는 호기심으로 **반복 플레이**가 발생한다.
- **가설 3**: 매일 바뀌는 **오늘의 AI 과제**(로봇이 묻는 질문에 답하기)를 완료하면 셀을 받고, 이 셀로 부품을 사서 로봇을 꾸미면 **획득처 확대 + 소비 촉진**이 동시에 일어난다.
- 기대 효과: 재접속률 · 체류시간 · 셀 사용량 증가 (기업 평가지표와 직결)

## ③ 학습과제(learning issues) — 앞으로 학습할 것

- LLM API(Gemini 3.5 Flash-Lite / DeepSeek) 활용: 색 조합 → 성격·대사 생성 프롬프트 설계, **실패 시 규칙 엔진으로 자동 전환**되는 이중 구조
- 데이터베이스 설계: 9개 테이블(users/robots/cell_tx/daily_quests 등), 특히 **셀 거래 내역(cell_tx) 기반 재화 흐름 추적**
- Express 기반 REST API 설계와 역할별 화면 구조(만들기/마이룸/상점/리포트)
- SVG 캐릭터의 부위별 색칠 인터랙션 구현
- 효과 검증 지표(재접속율·체류시간·셀 사용량)를 위한 접속 로깅 설계
