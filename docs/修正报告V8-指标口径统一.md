## 二、수정 내용

### 1. 공용 지표 함수 신설 (단일 진실 공급원)
`server.js` 1115행~ 에 `metricsFor(uid)` 한 곳으로 모으고, **4개 경로가 전부 이 함수만 쓰도록** 변경.

```js
const TEST_USER_SQL = "nickname NOT LIKE '시연%' AND nickname <> '데모_루미'";
const RETURN_RATE_DEF = '재접속률 = 활동일수 ÷ 경과일수(가입일~오늘, 가입 당일 포함) × 100';
function cappedDurationSec(uid){ /* 하루 단위 MIN(SUM(duration), 40분) 합 */ }
function metricsFor(uid){ /* activeDays·returnRate·playMin·playMinRaw·quests·games … */ }
function allUserRows(){ /* 데모·시연 제외 + 지표 부착 */ }
function meanOf(rows,f){ /* 활동 계정만의 개인별 단순 평균 */ }
```
- `/api/admin/stats`, `/api/admin/export.csv`, `/api/public/stats` → 공용 함수 사용으로 **전면 교체**
- `/api/board/me` → 같은 정의 사용
- **재접속률 정의 확정**：`활동일수 ÷ 경과일수`. 매일 접속하면 **정확히 100%** (기존 정의는 도달 불가)

### 2. 체류시간 상한을 정책과 일치시킴
```js
const PLAY_CAP_SEC      = DAILY_PLAY_LIMIT * 60;      // 하루 인정 체류 = 40분
const PLAY_HARD_CAP_MIN = DAILY_PLAY_LIMIT * 6;       // 측정 보존용 안전 상한 240분
```
- `/api/visit/duration`：보고 상한 **2시간 → 40분**
- 지표 계산：**하루 단위로 40분까지만 인정** (탭 방치 시간 제거)
- **원값은 `playMinRaw` 로 보존** → 상한 적용 전후를 둘 다 확인 가능(발표 시 근거로 제시 가능)

### 3. 40분 제한 집행은 그대로 (측정값을 자르지 않음)
```js
// 예전: const capped = Math.min(DAILY_PLAY_LIMIT, next);  ← 41분도 200분도 전부 '40'으로 기록
// 지금: 안전 상한까지만 저장하고, 제한은 비교로 판정
const stored = Math.min(PLAY_HARD_CAP_MIN, next);
res.json({ ok:true, playMinutes: stored, limit: DAILY_PLAY_LIMIT, over: stored >= DAILY_PLAY_LIMIT });
```
→ **집행 동작 100% 동일**, 다만 41분과 200분을 구분할 수 있게 됨(측정값이 살아남)

### 4. CSV 컬럼 확장
`spanDays`, `playMinRaw`, `visits` 추가 (총 20열). 기존 `returnRate`·`playMin` 은 공용 함수 값.

### 개인별 값 정확성
| 계정 | activeDays | spanDays | returnRate | playMin | playMinRaw |
|---|---|---|---|---|---|
| 학생A | 3 | 5 | **60%** | **60** | 150 |
| 학생B | 1 | 1 | **100%** | 5 | 5 |
| 빈계정 | 0 | 1 | 0% | 0 | 0 |

- 학생A：5일 중 3일 활동 → 60% (설계 의도대로)
- 학생B：가입 당일 활동 → **100%** ← 기존 정의로는 도달 불가능했던 값
- 학생A 체류：600+600+7800초 = 150분 → **10+10+40 = 60분** 으로 상한 적용 ✅

## 四、⚠️ 배포 반영에 서버 재시작이 필요하다

`public/` 정적 파일은 자동 동기화되지만, **Node 서버 프로세스는 재시작해야 새 `server.js` 가 반영된다.**

확인 결과 현재 라이브는 아직 구 코드:
```
GET /api/public/stats  →  {"participants":13,"avgReturnRate":13,"avgPlayMinutes":81,...}
                            ↑ definition 필드 없음 = 구 코드
```

**재시작 후 예상 변화**（정의가 바뀌므로 숫자가 달라진다）
- `avgReturnRate`：13% → **활동일수÷경과일수 기준으로 재계산** (대체로 상승, 매일 접속 계정은 100%)
- `avgPlayMinutes`：81분 → **40분 이하** (하루 상한 적용)
- `definition` · `playNote` 필드가 응답에 추가됨

> 재시작 전후 숫자가 달라지므로, **W13 효과 검증 표는 재시작 이후 값으로 작성**해야 한다. 두 기준을 섞으면 다시 모순이 생긴다.
