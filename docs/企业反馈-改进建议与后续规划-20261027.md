## 一、反馈原文要点（不改写）

**截图 1（疑虑）**

1. 不清楚“我的房间”里的机器人打算怎么处理；孩子**缺乏饲养机器人的动力**。
2. 赋予机器人 AI 人格以解释“饲养好处”，但从之前看到的原型看，**还需要大量开发工作**。
3. 需要考量机器人**能否胜任聊天机器人**的角色。
4. **游戏奖励获取机制**：没有展示实际游戏玩法，不清楚具体如何实现。

**截图 2（方向）**  
5\. “让机器人作为**辅助学习的 AI 伙伴**会更加合适。”  
6\. 孩子在学习内容/上课时会卡住；AI 伙伴能**帮助解决困难**是好方向。  
7\. “RooMi 不仅是陪伴和养成机器人，而是能在孩子遇到学习困难时**提供实际帮助的 AI 学习助手**。”  
8\. 例：做编程任务卡住 → 向机器人提问 → **不直接给答案，而是通过解释和提示**帮助理解。  
9\. “既能体现 AI 的实际价值，也能保留机器人的陪伴功能。”

## 四、改进建议（产品 / 技术 / 演示三层）

### 4.1 产品层：主循环重构（“饲养”→“共学”）

|      | 旧循环（外部质疑）        | 新循环（建议）              |
| ---- | ---------------- | -------------------- |
| 触发   | 想喂机器人            | **学习卡住**（作业/编程/课堂）   |
| 行为   | feed / praise 点击 | 向 RooMi 提问，逐级要提示     |
| 反馈   | +셀、台词            | **理解值↑ + 机器人成长 + 셀** |
| 次日理由 | 连续登录奖励           | **“昨天那题我懂了，今天再问一个”** |

- **“饲养”降级为副循环**：喂食/夸奖保留，但只给情绪反馈与少量셀，不再承担成长主轴。
- **“共学”升级为主循环**：孩子每“自己解决”一题，机器人 `understanding` +1；到阈值升级 stage，直接呼应“成长经验”。
- **装饰/商店仍是情感表达**：但购买动机改为“把一起学习的伙伴打扮起来”，而非“打发时间”。

### 4.2 技术层：把 `/api/workshop/ask` 升级为“提示阶梯”

**现状（`server.js` L1446–1465）**：prompt 要求“两句话回答”，直接给答案；`sanitizeLine(140)`；5 次/天。

**改造设计（不新增第 39 个端点，扩展现有端点）**

```
POST /api/workshop/ask
body: { question, mode:'learn', subject:'coding'|'math'|'class',
        hintLevel:1|2|3, taskId?, context? }
resp: { ok, level, hintType:'clarify'|'concept'|'nextstep',
        text, canAdvance, left }
```

- **L1 澄清**：反问“你想让机器人重复几次？”——不给知识。
- **L2 概念**：用生活类比解释“循环=把同一件事做很多遍”。
- **L3 下一步**：只给一步可执行动作“先把 3 次写出来试试”。
- **永不给完整答案**；`hintLevel` 由前端“再提示一点”按钮推进，服务端校验不可跳级。
- **安全**：沿用 `isSafeText`/`sanitizeLine`；新增“答案泄露检测”（若输出含完整代码/最终数值则降级为 L3）。
- **频控**：沿用 5 次/天；同题同级别不重复计次。
- **人格影响语气**：6 种性格 → 3 种提示风格（鼓励型/严谨型/幽默型），这是“AI 人格”的真实用途，而非通用闲聊。

**新增 1 张表（当时 16 表；现总计 21 表）**

```
learning_help_logs(id, user_id, day, subject, level, solved, ts)
INDEX(user_id, day)
```

- `solved=1` 由前端“我懂了/我做出来了”按钮回传；用于算“提示后自解率”。

**成长绑定**：`users` 加 `understanding`（或用现有 `exp`），规则：

- 提示后自解 +3 understanding；直接看答案 +0；
- 每 10 点升 1 stage（与现有 1–3/4–7/8+ 对齐）；
- 学习求助每日最多计 3 次成长，防刷。

### 4.3 演示层：把“没展示”变成“可展示”（P0 最快见效）

1. **90 秒 demo 脚本**（录屏，不用现场 3D）：
   - 0–10s 登录 → 本周主题「멈춘 기계의 노래」
   - 10–25s 编程任务卡住（循环次数写错）
   - 25–50s 问 RooMi → L1 反问 → L2 类比 → L3 下一步
   - 50–70s 孩子自己改对 → +셀、机器人成长动画
   - 70–85s 用셀买部件装饰 → 展示“陪伴”仍在
   - 85–90s 显示明日 streak
2. **1 页 flow 图**：`卡住 → 提问 → 提示 → 自解 → 成长/셀 → 次日`。
3. **游戏奖励 1 页表**：反사 10/20/30/40/50；기억 50/60/70/80/90/100/110；每日各 1 次；셀→부품/장식/스킨。
4. **3 个场景脚本**：编程（循环）、数学（应用题）、课堂（本周主题提问）。

## 九、与现有材料的冲突处理

- **deck p.3/p.7 已写“공작소 AI/수업도 콘텐츠”**，但外部反馈“没看到玩法”→ 问题在**演示**，不在实现；P0 补视频即可。
- **`/api/workshop/ask` 现为“直接回答”** → 必须改成提示阶梯，否则与“不直接给答案”的产品目标相反。
- **`feed/praise` 仍是任务** → 降级为副循环，不再作为成长主路径；否则“饲养动力不足”无解。
- **README / `server.js` 头注释** → 已同步为 **21 表**。

## 十、结论

外部反馈的核心不是“功能不够”，而是“**价值主张不对 + 关键玩法没看到**”。

- **48 小时内可交付**：新定位 + 3 级提示阶梯 + 90 秒 demo + 1 页 flow（P0）。
- **1 周内可闭环**：学习求助记录 + 成长绑定 + 双入口（P1）。
- **2–4 周可完善**：单学科模板 + 内部场景自测（P2）。

这样既保留“机器人住在마이룸”的陪伴感，又把 AI 从“装饰性人格”变成“孩子卡住时的实际帮助”，回应外部反馈的 5 个疑虑。

### 11.6 明确不借鉴（防 scope creep）

| 不借鉴           | 原因                                   |
| ------------- | ------------------------------------ |
| 开放 3D 世界（3 组） | 工作量与风险过高；我们的差异化是“一个会因学习而改变的房间”       |
| 多人协作/世界聊天     | 安全、审核、服务器成本；单人 + 机器人已足够              |
| 完整主题公园经营模拟    | 会把“学习伙伴”带偏成“经营游戏”；只做轻量功能化            |
| 2D 雷霆战机新类型    | 换类型成本高；借“街机手感”即可                     |
| 真实接入 DOROBUS  | **不做企业接入**（2026-10-27 决定）；只做自有产品 |

### 11.7 借鉴后的结论

- 他组强在**世界规模**与**游戏手感**；我们强在**机器人陪伴 + 学习提示**。
- 因此不打“开放世界”的仗，&#x6253;**“学习让房间亮起来”**&#x8FD9;一仗：
  - 目标“成长经验”→ 房间灯光/书架/机器人 stage 直接可见；
  - 目标“不直接给答案”→ hint token + 三级提示；
  - 目标“看到玩法”→ 四幕 demo + 街机化小游戏。
- 这样既不落后于他组的“可看性”，又保持 RooMi 的差异：**不是更大的世界，而是更懂你的房间。**


## 十二、小游戏重做与 UI 2.0 方案（2026-10-27 新增）

> 本节**取代 §11.3 第 6 项“小游戏街机化”**的轻量方案。范围：**自有产品**，不考虑企业接入。

### 12.1 结论

| 项 | 决定 |
|---|---|
| 小游戏 | **淘汰 반사/기억** → 《버그 슈터》(2D 纵版射击) + 《오늘의 퍼즐》(学习型四选一) |
| 射击游戏 | 做，但主题化为“버그 슈터”，不照抄雷霆战机；程序化图形、无外部素材 |

### 12.2 现有小游戏诊断

| 游戏 | 现状 | 问题 | 代码 |
|---|---|---|---|

### 12.3 新游戏

**A.《버그 슈터》— 2D 纵版射击（主推）**

| 项 | 设计 |
|---|---|
| 主题 | 「코드 우주를 지켜라」：玩家=루미 ship；敌人=버그/글리치/바이러스；子弹=수정(fix) |

| 奖励 | 10/20/30/50/80/110셀；每日 1 次计奖，额外局只记排行 |
| 技术 | **Canvas 2D**，零新依赖；复用 `submitGameResult` + `game_logs.kind='shooter'` |

**B.《오늘의 퍼즐》— 学习型（替代 기억）**

| 奖励 | 答对 +30셀 + understanding；答错不扣 |
| 技术 | 复用现有 modal + `daily_quests.topic`，1–2d |

**C. 旧游戏处理**：删除 `#game-reflex`、`#game-memory` 入口与代码（保留 git 历史）。

### 12.15 AI 주도 학습 계획 (2026-10-28)

**왜**: 채팅이 "아이가 먼저 말 걸기"만 가능해 수동적. AI가 오늘의 계획을 먼저 짜서 제시.

**동작**
- 마이룸 진입 시 `GET /api/plan/today` → AI가 3단계 계획 생성(8~12분)
- 입력: 레벨/이해도/최근 해결 개념/약점/이번 주 주제
- 단계 type: `concept`(채팅 개념) · `puzzle`(오늘의 퍼즐) · `review`(복습) · `game`(두더지/슈터)
- 계획 카드: 단계별 «시작» + 체크; 3단계 완료 시 +10셀(1/일)
- 오후 4시 이후 아직 시작 전이면 토스트 1회: "오늘의 학습 계획이 준비됐어!"
- 채팅 첫 오프너: "오늘의 계획 1단계: … 같이 시작해 볼까?"
- 퍼즐 2회 오답 → "루미에게 묻기"로 개념 채팅 연결

**폴백**: LLM 실패/무키면 규칙 기반 3단계(개념→퍼즐→복습).

**검증**: 실제 DeepSeek 1.88초·3단계 생성, 3단계 완료 +10셀, 폴백 3단계, UI 오류 0.

## 十三、LLM 能力扩展：从“单轮问答”到“学习伙伴”（2026-10-27 新增）

> 用户判断：LLM 接入要做出更多功能——RooMi 不只是升级/陪伴，还要**解答学习问题 + 聊天，像真的 LLM 一样**。这是本项目最重要的差异化。  
> 原则：**不做通用 ChatGPT**，做“儿童安全 + 课程绑定 + 不给答案”的学习对话引擎。

### 13.1 现状与差距（代码事实）

| 能力           | 现状                                                         | 差距                           |
| ------------ | ---------------------------------------------------------- | ---------------------------- |
| 对话轮次         | `callGemini(prompt)` 单轮字符串；`/api/workshop/ask` 只发一条 prompt | **无历史/无上下文**，不能连续追问          |
| 模式           | 只有“问一句、答两句”（`maxOutputTokens:300`，`sanitizeLine(140)`）     | 无“聊天/学习/情绪”模式区分              |
| 学习者记忆        | 无                                                          | 不知道孩子卡在哪、偏好什么语气              |
| 知识 grounding | 靠模型通识                                                      | 未绑定 `weekly_topics`/教材/编程概念  |
| 输出控制         | `sanitizeLine` 只截首行 + 黑名单                                  | 无 JSON schema、无“禁止直接给答案”的强校验 |
| 安全           | `isSafeText`（200 字、6 位数字、URL、暴力/色情/毒品/赌博/个人信息）             | 无儿童向输出审核、无危机升级路径             |
| 成本/延迟        | 4 级 Gemini（490/490/20/20）→ DeepSeek → 预设；8s 预算；10 分钟熔断     | 无按模式路由、无 token/成本日志、无缓存      |
| 体验           | 无 typing/streaming                                         | 不像“真的 LLM”                   |

### 13.2 目标能力（3 模式 + 4 技能）

**3 模式**

| 模式            | 用途         | 语气          | 限制               |
| ------------- | ---------- | ----------- | ---------------- |
| **수다（聊天）**    | 情绪陪伴、日常对话  | 温暖、短句、2–4 句 | 10 次/日；不涉敏感话题    |
| **같이 공부（学习）** | 学习卡点、概念、代码 | 提问式、鼓励      | 5 次/日；**不直接给答案** |
| **마음 체크（情绪）** | 每日心情/压力    | 倾听、1 个问题    | 1 次/日；不做诊断       |

**4 技能**

1. **개념 설명**：用生活类比 + 例子 + 1 个检查问题。
2. **단계적 힌트**：L1 澄清 → L2 概念/类比 → L3 下一步；永不给完整答案。
3. **코드 디버깅 도움**：让孩子贴代码/描述报错 → 指出“先检查哪一行”，不直接改。
4. **퀴즈 생성**：从本周主题生成 3 题，带 3 个 hint token。

### 13.3 目标架构

```
[My Room 채팅 패널]
   │ POST /api/chat {mode, message, hintLevel, context}
   ▼
[프롬프트 빌더]
   ├─ 페르소나(이름/성격/단계)
   ├─ 모드 규칙(수다/공부/마음)
   ├─ 학습자 프로필(레벨·약점·힌트 스타일)
   ├─ RAG-lite 지식 카드 top3(주제·개념)
   └─ 최근 6턴 대화
   ▼
[모델] deepseek-chat 단일 호출(비추론, §14) → 캐시/프리셋
   ▼
[JSON 파서/검증] {reply, hintLevel, followUp, safety}
   ▼
[안전 필터] isSafeText + sanitizeLine + 스키마 + “정답 포함” 검사
   ▼
[응답] 타이핑 효과 + 후속 질문 칩
```

### 13.4 数据模型（新增 4 表，均按 user_id 归属）

```sql
-- 단기 기억(최근 대화). 30일 보관, 계정 삭제 시 함께 삭제
CREATE TABLE IF NOT EXISTS chat_messages(
  id INTEGER PRIMARY KEY, user_id INTEGER, role TEXT,      -- 'user'|'assistant'
  content TEXT, mode TEXT, hint_level INTEGER, ts TEXT
);
CREATE INDEX IF NOT EXISTS idx_chat_user_ts ON chat_messages(user_id, ts);

-- 장기 기억(학습자 프로필). 대화 요약은 last_summary 에 1~2문장으로 압축
CREATE TABLE IF NOT EXISTS learner_profile(
  user_id INTEGER PRIMARY KEY, understanding INTEGER DEFAULT 0,
  weak_topics TEXT, hint_style TEXT, last_summary TEXT, updated_at TEXT
);

-- RAG-lite 지식 카드(운영자가 추가/수정). 벡터DB 없이 topic+keyword 매칭
CREATE TABLE IF NOT EXISTS knowledge_cards(
  id INTEGER PRIMARY KEY, topic TEXT, chapter INTEGER, concept TEXT,
  analogy TEXT, example TEXT, hint_l1 TEXT, hint_l2 TEXT, hint_l3 TEXT, tags TEXT
);

-- 비용/품질 로그(모델·토큰·지연). 민감정보 없음
CREATE TABLE IF NOT EXISTS llm_logs(
  id INTEGER PRIMARY KEY, user_id INTEGER, mode TEXT, model TEXT,
  in_tokens INTEGER, out_tokens INTEGER, latency_ms INTEGER, ok INTEGER, ts TEXT
);
```

### 13.5 Prompt 架构（关键：模式规则 + 结构化输出）

**系统提示（韩语，可按需中文化）**

```
너는 DOROBUS의 로봇 "루미"(성격: {personality}, 단계: {stage})다.
대상: 초등 고학년(10–13세). 짧고 쉬운 한국어, 한 번에 2–4문장.
이번 주 주제: {topic}(CH.{chapter}). 아이 수준: Lv.{level}, 약점: {weakTopics}.

[모드=수다] 공감 먼저, 설명 금지. 민감한 주제는 "그건 선생님/보호자와 이야기하자"로.
[모드=공부] 절대 최종 정답을 말하지 마라. 아래 3단계만:
  L1: 아이에게 되묻기(무엇을 하려는지 확인)
  L2: 생활 비유로 개념 설명(예: 반복문=같은 일을 여러 번)
  L3: 다음 한 단계만 제안(예: "3번 반복부터 써 보자")
  마지막에 스스로 확인할 질문 1개.
[모드=마음] 판단/조언 금지. 1문장 공감 + 1개 질문. 위험 신호는 고정 안내문.

[지식 카드]
{top3 cards: concept / analogy / example / hint_l1..3}

[최근 대화]
{last 6 turns}

[출력] JSON만:
{"reply":"...","hintLevel":1|2|3|null,"followUp":"...","safety":"ok"}
```


**解析与降级**

1. 提取 `{...}` → `JSON.parse`。
2. 字段校验：`reply` 非空、长度 ≤180；`hintLevel` ∈ {1,2,3,null}；`safety==='ok'`。
3. `sanitizeLine(reply, 180)`；失败 → 预设台词。
4. **答案泄露检测**（学习模式）：若回复含完整代码块/最终数值/“정답은” → 降级为 L3 提示。
5. JSON 解析失败 → 把纯文本经 `sanitizeLine` 后返回，不让对话中断。

### 13.6 RAG-lite（不引入向量库）

| 项    | 做法                                                            |
| ---- | ------------------------------------------------------------- |
| 知识来源 | 运营者维护 `knowledge_cards`：本周主题、编程概念（변수/반복문/조건문/함수/디버깅）          |
| 检索   | `topic` 精确 + `tags`/`concept` LIKE；取 top 3；无命中则只用模型通识         |
| 注入   | 把 `concept/analogy/example/hint_l1..3` 放进 prompt，要求“优先使用卡片内容” |
| 扩展   | 后续可加 embedding；当前规模（<200 卡）SQL 足够                             |
| 运营   | 复用 `/api/admin/topic` 模式，新增 `/api/admin/card` CRUD            |

**为什么不做向量库**：卡片少、主题固定、延迟敏感；SQL 匹配 + 人工卡片质量更高、可解释、零依赖。

### 13.7 安全与儿童保护（硬约束）

| 层    | 规则                                                     |
| ---- | ------------------------------------------------------ |
| 输入   | `isSafeText`（沿用）+ 长度 ≤200 + 6 位以上数字拦截                  |
| 输出   | `sanitizeLine` + 黑名单 + 禁外链 + 禁个人信息 + 禁暴力/色情/毒品/赌博      |
| 学习模式 | **禁止直接给答案**：检测完整代码/最终数值/“정답은” → 降级                     |
| 危机信号 | 自伤/虐待/极端词 → **不调用 LLM**，返回固定安全话术 + 建议找保护者/老师，并记录（不做诊断） |
| 频控   | 수다 10/日、공부 5/日、마음 1/日；单条 1 请求，不自动重试                    |
| 隐私   | 只存昵称 + 对话；30 天保留；账号删除即删；不收集实名/电话/地址/学校                 |
| 依赖防治 | 学习模式必须“先让孩子尝试”；连续 3 次直接要答案 → 转“和老师/同学一起”               |

### 13.8 成本 / 延迟控制

| 项    | 策略                                                        |
| ---- | --------------------------------------------------------- |
| 模型路由 | **仅 DeepSeek `deepseek-chat`（非 reasoner，见 §14）**；不做多模型升级链 |
| 预算   | 总 8s（沿用）；输出 ≤300 tokens；输入 ≤1200 tokens；历史只带最近 6 轮        |
| 记忆压缩 | 超过 6 轮 → 用 1 句 `last_summary` 替代旧轮次                       |
| 缓存   | 常见问题 hash 缓存 10 分钟；主题变更即失效                                |
| 降级   | 全链失败 → DeepSeek → 预设台词；>4s 未回 → 预设 + “생각 중”动画             |
| 成本上限 | 全局 500 次/日；单用户 15 次/日；`llm_logs` 每日汇总                     |

### 13.9 UX（“像真的 LLM”）

- **入口**：마이룸 底部聊天条 + 공작소 “같이 공부” tab；随时可唤起。
- **气泡**：用户右、RooMi 左；打字指示器（● ● ●）；机器人头像随情绪变化（思考/开心）。
- **模式切换**：`수다 · 같이 공부 · 마음 체크` 三个 chip。
- **学习工具条**：`힌트 3개`、`더 쉽게`、`예시 보여줘`、`내가 해볼게`。
- **后续问题**：每次回复带 1–2 个可点击的 follow-up chip（“왜 그런지 더 알려줘”）。
- **流式**：v1 用前端打字动画；v2 可接 SSE 真流式。
- **人格语气**：6 种性格 → 3 种语气（활발/차분/엉뚱），影响措辞不影响规则。

### 13.10 演示场景（3 个，各 30 秒）

| 场景        | 用户说         | RooMi 回（要点）                                              |
| --------- | ----------- | -------------------------------------------------------- |
| **코딩 막힘** | “반복문이 안 돼요” | L1 “몇 번 반복하려고 했어?” → L2 “반복문=같은 일 여러 번” → L3 “3번부터 써 보자” |
| **개념 질문** | “변수가 뭐예요?”  | 类比“이름표 붙은 상자” + 例子 + “그럼 네 이름은 어떤 상자에 담을까?”              |
| **수다/감정** | “오늘 시험 망쳤어” | 共情 2 句 + “지금 기분이 어때?” + 建议休息/找保护者（不诊断）                   |

> 这三个场景直接回应外部反馈的“能否胜任聊天 + 能否给学习帮助”两个疑虑。

### 13.11 评估指标（可 SQL/抽样）

| 指标            | 目标                     |
| ------------- | ---------------------- |
| 安全通过率（抽样）     | 100%                   |
| 学习模式“未直接给答案”率 | ≥95%                   |
| 回答相关性（人工 1–5） | ≥4.0                   |
| p95 延迟        | <3s（降级 <4s）            |
| 每条成本          | ≤0.02 元（按模型计价）         |
| 人均消息/日        | 3–8                    |
| 提示后自解率        | ≥50%（配合 understanding） |
| 次日再对话率        | ≥30%                   |

### 13.12 实施步骤

| 阶段           | 内容                                                                     | 工作量  | 验收             |
| ------------ | ---------------------------------------------------------------------- | ---- | -------------- |
| **P0（3–4d）** | `/api/chat` 统一入口（3 模式）；最近 6 轮；JSON schema；安全过滤；마이룸 聊天面板；3 场景录屏         | 3–4d | 能连续追问，学习模式不给答案 |
| **P1（1w）**   | `learner_profile` + `knowledge_cards`（30 张）；hint token；记忆压缩；`llm_logs` | 5d   | 个性化+课程绑定       |
| **P2（2w）**   | 评估集（50 问）；多学科卡片；真流式/TTS；教师端卡点报告                                        | 5d   | 质量/成本可解释       |

### 13.13 风险与对策

| 风险                 | 对策                                            |
| ------------------ | --------------------------------------------- |
| 幻觉/错误知识            | RAG 卡片优先；不确定时“一起查/问老师”；不装作知道                  |
| 儿童安全               | 输入/输出双过滤 + 危机固定话术 + 频控 + 家长门                  |
| 依赖 AI、不肯自己想        | 学习模式强制 L1 先反问；3 次直要给答案 → 转人工                  |
| 成本/延迟              | 单模型 DeepSeek + 缓存 + 6 轮记忆 + 6s 超时 + 预设降级（§14） |
| 隐私                 | 只存昵称+对话，30 天，删除即清                             |
| “像 ChatGPT”被视为通用聊天 | 明确边界：课程主题、儿童语气、不给答案、无外链                       |

### 13.14 结论

- **这是本项目最该投的能力**：他组强在 UI/世界，我们强在“会教、会陪、不给答案”的对话。
- **不新建一套系统**：在现有 `callGemini`/`callDeepSeek`/`isSafeText`/`sanitizeLine`/`weekly_topics` 上扩展，改造成本低。
- **P0 四天可演示**：三个场景（코딩 막힘/개념/수다）就能让人看到“真的 LLM + 真的学习帮助”。
- **一句话**：让 RooMi 从“会说话的装饰”变成“**会提问、会等你想、会陪你聊**的学习伙伴”。

- 更小 `max_tokens`（180–220）。
- 可选 JSON mode（若 API 支持；不支持则回退“提取 `{...}` + `JSON.parse`”）。
- **但**：DeepSeek 在韩国/亚洲的 p50/p95 需实测；若比 Gemini 慢，应暂停切换，而不是硬切。

### 14.6 Prompt 调整（非推理模型的关键）

非推理模型更容易“直接给答案”，学习模式必须加固：

1. 明确写“**정답을 말하지 마라**”，只给 L1/L2/L3。
2. 强制 JSON：`{reply, hintLevel, followUp, safety}`；`hintLevel` 必填。
3. **答案泄露检测**：回复含完整代码块/最终数值/“정답은” → 降级为 L3。
4. 上下文缩到 4–6 轮，减少干扰。
5. 韩语短句、儿童词汇、避免敬语堆叠。
6. 温度：学习 0.7（稳定）、聊天 0.9（自然）；输出 180–220 tokens。

### 14.7 迁移步骤（直接切换，不做基准）

| **P0 直接切换** | 删除 Gemini 代码/配置；`callLLM()` 固定 `deepseek-chat`；更新所有调用点 | 0.5d |
| **P1 清理**   | 删 `gemini_key.txt`/`GEMINI_*` 环境变量/文档；更新部署命令           | 0.5d |
| **P2 回归**   | 安全/延迟/质量/降级全测（切换后做，不做事前基准）                             | 0.5d |

> 按要求**不做基准测试，直接切换**。回归测试放在切换后：若发现韩语质量或延迟问题，调整 prompt/超时/缓存，**不回退 Gemini**。

### 14.8 验收标准

- `grep -ri "gemini" server.js public/ package.json` = 0（文档/历史除外）。
- 仅 `deepseek-chat`，无 `deepseek-reasoner`。
- p95 < 2.5s（目标；以实测为准）。
- 失败时 3s 内出预设台词，不空白。
- 50 问评测 ≥4/5；安全抽样 100%。
- 日成本/调用量在预算内。

### 14.9 对 §13 的影响

- §13.3/§13.8 的“Gemini 路由”已改为“仅 DeepSeek”。
- 3 模式/记忆/RAG/JSON 结构不变；但**提示词与答案泄露检测需加强**（非推理模型更易直答）。
- 流式体验：DeepSeek 支持 stream；v1 仍用前端打字动画，v2 可接 SSE。

### 14.10 结论

- 单供应商更简单、可能更快，但**单点故障 + 韩语质量 + 延迟**三项必须先测。
- 执行路径：**直接硬删 Gemini → 切 `deepseek-chat` → 0.5 天回归**（不做基准测试）。
- 若回归发现问题：调 prompt/超时/缓存；**不回退 Gemini**。
