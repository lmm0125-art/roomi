## ① 성장 단계가 이제 로봇 외형에 반영된다

### 무엇을 바꿨나
`buildRobotModel(...)` 에 `stage` 인자를 추가하고, 부품을 붙이기 직전에 단계별 변환을 적용한다.

```js
const G = { 1:{s:0.86,eye:1.18,ant:0.62},   // 아기   — 작고, 눈 크고, 안테나 짧다
            2:{s:1.00,eye:1.00,ant:1.00},   // 청소년 — 기존 비율
            3:{s:1.10,eye:0.92,ant:1.38} }  // 성체   — 크고, 눈 작고, 안테나 길다
parent.scaling.x = parent.scaling.y = parent.scaling.z = G.s;
antRod.scaling.y = G.ant;
antBall.position.y = hy + 0.62 + 0.225*G.ant + 0.075;   // 공이 로드 끝에 붙어 있게
eyeL.scaling.x = eyeR.scaling.x = G.eye;                // 깜빡임은 scaling.y → 충돌 없음
```
호출부 3곳(마이룸 재빌드 / 최초 3D / 상점 미리보기) 모두 `curStage()` 를 넘긴다.

### 소유권 충돌을 피한 방법
`model.scaling.y` 는 **`updateIdle` 의 '호흡'이 매 프레임 다시 쓰는 속성**이다. 여기서 y 를 따로 대입하면 호흡이 덮어써 성장이 사라진다 — 이 프로젝트가 `root.position.y` 와 점프 애니메이션에서 두 번 겪은 바로 그 문제다.
→ 배율을 `refs.growthScale` 로 넘기고, 호흡이 **곱해서** 쓰도록 단일 공식을 만들었다.
```js
refs.model.scaling.y = (refs.growthScale||1) * (1 + Math.sin(t*1.6)*0.013);
```

### 헤드리스 실측 (Babylon NullEngine, 실제 메시 생성 후 월드 바운딩박스)
```
아기   (stage 1): 전체높이 2.653  폭 1.345  눈크기 1.18  scale 0.86  메시 15
청소년 (stage 2): 전체높이 3.170  폭 1.564  눈크기 1.00  scale 1.00  메시 15
성체   (stage 3): 전체높이 3.581  폭 1.721  눈크기 0.92  scale 1.10  메시 15
⇒ 아기 → 성체 높이 변화율 135% (2.65 → 3.58)
```
4개 템플릿 전부 확인:
```
doro 2.65→3.58 ✅   roundy 2.61→3.53 ✅   boxy 2.65→3.58 ✅   tally 2.78→3.75 ✅
```
메시 수는 15개로 단계와 무관 → **구조를 바꾸지 않고 비례만 바꿨다**(기존 애니메이션·충돌 없음).

### 검증 중 발견해서 고친 결함
처음엔 `scaling.x/z` 만 설정하고 y 는 호흡에 맡겼다. 헤드리스 실측을 돌려 보니 **높이 변화가 5.5% 뿐**이었다 — 호흡이 한 번 돌기 전에는 세로 성장이 0 이었기 때문이다. `scaling.y` 도 함께 초기화해서 **35%** 로 정상화했다.
> 코드만 읽었으면 "x/z 만 건드리니 안전하다"고 판단하고 넘어갔을 부분이다. **바운딩박스를 실측하지 않으면 안 보이는 종류**였다(이 프로젝트가 MeshBuilder 옵션 오타 때 배운 것과 같다).

## ② 스트릭 7칸 달력 — "내일 받을 보상"을 미리 보여준다

### 서버
`/api/growth/me` 에 표와 위치를 실어 보낸다(예전엔 표가 서버에만 있었다).
```
streakTable {1:10,2:15,3:25,4:35,5:50,6:60,7:100} · streakCycle 7
streakDoneSlot(오늘까지 채운 칸) · streakNextSlot · streakNextReward · streakMaster 200
```
실측 검증:
```
streak= 0 → done 0 · next 1 · 내일 +10   ✅
streak= 3 → done 3 · next 4 · 내일 +35   ✅
streak= 7 → done 7 · next 1 · 내일 +10   ✅  (7일 주기 순환)
streak= 8 → done 1 · next 2 · 내일 +15   ✅
streak=14 → done 7 · next 1 · 내일 +10   ✅
```

### 클라이언트 (마이룸 사이드바)
렌더 출력 실측:
```
streak=3 → 🔥 3일 연속 · 내일 +35셀
           [10✓][15✓][25✓][35▲][50·][60·][100·]
streak=7 → 🔥 7일 연속 · 내일 +10셀
           [10▲][15✓][25✓][35✓][50✓][60✓][100✓]   ← 내일부터 새 주기
```
7일을 다 채운 날에는 `next`(1일차)가 `done` 과 겹치므로 **next 를 우선 표시**해 "새 주기 시작"이 항상 보이게 했다. 표가 없을 때(초기 상태)는 빈 문자열로 안전하게 빠진다.

## ③ 부품 보너스 — 광고한 +10 이 실제로 도달 가능해졌다

`COUNT(*)`(행 수) → `COALESCE(SUM(v.qty),0)`(수량 합계). 부품 종류가 3개뿐이라 행 수 기준으로는 **+6 에서 멈췄고**, 교환으로 중복을 늘려도 같은 행의 qty 만 증가해 보너스가 오르지 않았다.

실측:
```
안테나 리본 → +2   로켓 부스터 → +4   나사 장식 → +6     (3종 = 기존과 동일)
교환 1회(조각 3개) → +8
교환 2회(조각 3개) → +10          ← 광고한 상한 도달 ✅
```

그리고 **구매·교환 직후 `refreshGrowth()`** 를 호출해 배지가 즉시 갱신된다. 예전엔 `buyItem` 이 성장 수치를 다시 읽지 않아서 **부품을 사도 "⚙️ 과제 +N셀" 배지가 그대로**였다(다음 새로고침에야 반영). 계산만 고치고 표시를 안 고치면 의미가 없어서 함께 처리했다.

## ⚠️ 배포 반영에 재시작이 필요하다

```
로컬 app.js 139,351 bytes (md5 30f8c91f…)
라이브 app.js 135,407 bytes (md5 6765a487…)   ← 아직 이전 버전
라이브에서 renderStreakCal / curStage / growthScale = 0건
```
**앱을 재시작(또는 재발행)해야** 프런트·서버 변경이 모두 반영된다. 앞선 라운드의 지표 통일(V8)도 아직 라이브에 적용되지 않은 상태이므로, **한 번 재시작하면 두 라운드가 함께 반영**된다.

### ⚠️ 브라우저 육안 확인이 필요하다
3D 변환은 **헤드리스(NullEngine)로 바운딩박스 실측**까지 했지만, 실제 렌더링 화면은 제가 볼 수 없다. 재시작 후 **마이룸에 들어가** 아래를 확인해 주세요.
1. 로봇이 정상으로 보이는가(찌그러짐·부유 없음)
2. 데모 계정(`🎬 데모 계정으로 바로 보기`)이 **Lv.5 → stage 2(청소년)** 이므로, 새 계정(stage 1 아기)과 **크기가 눈에 띄게 다른가**
3. 마이룸 사이드바에 **7칸 달력**이 보이고, 내일 칸이 주황으로 강조되는가
4. 부품을 사면 **"⚙️ 과제 +N셀"** 숫자가 바로 올라가는가
5. 과제를 완료해 단계가 바뀌면 **"🌱 … 로 자랐어!"** 말풍선과 함께 로봇 크기가 변하는가
