## 二、🔎 신규 개선점 (이번에 처음 다루는 항목)

### 🔴 1. 데모 계정 시드가 없다 — **프로젝트의 핵심 논지가 데모 화면에서 안 보인다**

실측: 신규 계정으로 로봇을 만들고 리포트를 열면 이렇게 나온다.

```
balance      : 160
activeDays   : 1        ← 방문한 날짜 수
returnRate   : 0%       ← 재접속률
streak       : 1        ← 연속 방문
level / exp  : 1 / 30 / 100
questDone    : 0
daily 배열   : [{"d":"2026-10-07","visits":1,"secs":0}]   ← 추이 그래프 1칸
```

이 프로젝트가 회사에 파는 논지는 **「성장 경험 · 수집 · 재접속」** 세 가지인데, 신규 계정 데모에서는 **셋 다 0으로 보인다.** 성장바는 Lv.1, 재접속률 0%, 추이 그래프는 막대 1개, 거래내역 3건. 게다가 **리포트 화면은 W13 효과 검증의 증거 화면**인데 신규 계정에선 비어 있다.

**제안(약 30분)**：`?demo=1` 파라미터 또는 「체험 계정으로 보기」 버튼 → 아래를 시드
- Lv.5 / exp 중간, streak 7, 부품 2개 보유, 셀 300
- `visits` 를 **최근 7일에 분산** 1행씩 + `duration` 8~15분 → 재접속률·체류시간·추이 그래프가 실제로 그려짐
- `cell_tx` 에 획득/소비 내역 몇 건 → 셀 흐름 표가 채워짐

**투자 대비 효과가 가장 큰 항목**이다. 코드는 이미 다 있는데 "보여줄 데이터"만 없는 상태다.

### 🔴 2. 효과 검증용 집계·내보내기가 전혀 없다

API 라우트 **21개를 전수 확인** — 전부 `/api/…/me` 로 **본인 것만** 조회한다. 전체 사용자 집계 엔드포인트가 **0개**다.

W13에서 만들어야 하는 건 **「재접속률 / 체류시간 / 셀 사용량 / 과제 제출률」의 전후 비교표**인데, 지금은 SQLite를 손으로 쿼리하거나 DB 파일을 직접 열어야 한다. 테스트가 끝나고 나서 이걸 하려면 시간이 더 든다.

**제안(약 1시간)**：
- `GET /api/admin/stats` → 전체 사용자 수, 평균 재접속률, 평균 체류(분), 총 셀 획득/소비, 과제 제출률
- `GET /api/admin/export.csv` → `users` / `visits` / `cell_tx` / `quest_logs` 를 CSV로 (발표 자료·부록에 그대로 붙일 수 있음)
- 간단한 관리자 키(`ADMIN_KEY` 환경변수)만 걸면 충분

### 🔴 3. 교환 차익 — **상점 가격표가 무의미해진다**

실측 (신규 계정, 실제 API 호출):

```
조각 20셀 × 3 = 60셀
POST /api/shop/exchange {"partId": <로켓 부스터 id>}
→ {"ok":true,"part":"로켓 부스터","remaining":0,"qty":1}
```

`/api/shop/exchange-info` 가 **3개 부품을 전부 target 으로 내려주고**, `exchange` 는 `partId` 를 그대로 받는다.

| 부품 | 정가 | 조각 경로(60셀) | 차이 |
|---|---|---|---|
| 나사 장식 | 60 | 60 | 동일 |
| 안테나 리본 | 80 | 60 | **20셀 이득** |
| 로켓 부스터 | 120 | 60 | **60셀 이득 (50% 할인)** |

→ **이성적인 플레이어는 부품을 정가로 사지 않는다.** 상점의 부품 가격표가 장식용이 되고, "소비처 설계"라는 이 프로젝트의 핵심 논지가 약해진다.

**제안(택1, 각 10분)**
- ① 교환은 **랜덤 부품** 지급으로 변경(선택 불가) — 가장 간단하고 기획 의도("모으면 바꾼다")에도 맞음
- ② 조각 가격 20 → **40셀**(3개 = 120셀 = 최고가와 동일)
- ③ `partId` 를 **최저가 부품으로만** 제한

### 🟡 4. 태블릿에서 3D를 확대·이동할 수 없다

코드 확인 결과:
- **확대** = `canvas.addEventListener('wheel', …)` 뿐 → **핀치 제스처 없음**
- **이동(팬)** = `if(p.event.button===2)` → **오른쪽 드래그**, 터치에는 존재하지 않음
- 두 캔버스 모두 `touch-action:none`(`style.css:58, 117`) → 스크롤까지 차단

대상 사용자는 초등 고학년~중학생이고, 학교·가정에서 **태블릿을 쓰는 경우가 많다.** 지금은 회전만 되고 확대·이동이 안 된다. 발표장에서 태블릿으로 시연하면 바로 드러난다.

**제안**：Babylon 의 `PointerEventTypes` 로 두 손가락 핀치(radius) + 두 손가락 팬(target) 추가. 또는 최소한 `touch-action:pan-y` 로 완화.

### 🟡 5. 기억 게임이 **색상만**으로 구분된다 (색각이상 아동 불가)

`MEM_COLORS` 12색, 최대 11칸. 칸은 `<i class="pad">` 에 **배경색만** 있고 기호·숫자·모양이 없다. `#ff6b6b` / `#ffa94d` / `#ffe066` 처럼 인접 색이 있어 **색각이상 아동(남아 약 8%)은 순서를 구분할 수 없다.**

**제안(약 20분)**：칸마다 고유 기호를 함께 표시(★ ● ▲ ■ ◆ ✚ …) — 색과 무관하게 순서를 기억할 수 있게 된다. 평가기준 ④「아이 관점」에도 플러스.

### 🟡 6. 운영자 가이드가 없다 — 평가기준 ①「운영자가 내용을 추가·수정할 수 있는가」

구조는 **이미 충족**되어 있다: `items`(아이템·가격·consumable) / `daily_quests`(오늘의 과제·보상) / `robot_lines`(성격별 대사) **3개 테이블이 데이터 기반**이라 코드 수정 없이 내용을 바꿀 수 있다.

그런데 **관리자 화면도, "이렇게 추가하세요" 문서도 없다.** 그래서 발표에서 "운영자가 추가할 수 있습니다"를 **말로만 주장**하게 된다. 평가항목인데 증거가 없는 상태.

**제안(약 30분)**：1페이지 「운영자 가이드」 — 새 아이템 추가 / 새 대사 추가 / 보상 조정 **INSERT 예시 3줄**이면 충분. 발표 자료 부록에 그대로 넣는다.

### 🟡 7. AI 과제가 교육과정·세계관과 연결되지 않는다 — 평가기준 ③ 创意性

현재 질문은 "오늘 가장 재미있었던 일은?" 같은 **일반 일상 질문**이다. `server.js` 의 `MISSION_PRESETS` 와 LLM 프롬프트 어디에도 **DLS 수업 내용이나 DOROLAND 챕터**가 들어가지 않는다.

평가기준 ③은 "**세계관/수업과 연결**"을 명시적으로 요구한다. 지금은 "로봇이 매일 질문한다"까지만 있고 **교육과의 연결고리가 없다**.

**제안**：`daily_quests` 에 `topic` 컬럼을 두고, 그 주의 DLS 주제를 시드로 넣어 생성 → "이번 주 배운 것 중 신기했던 건?" 처럼 **수업과 이어지는 질문**이 나오게. 교사가 주제만 바꿔 넣을 수 있어 운영자 요구사항과도 맞물린다.

## 四、총평

이번 수정은 **정확했다.** 세 건 모두 원인을 정확히 짚었고(스코프 승격·정석 API 교체·문서 전면 갱신), 실측에서 복구를 확인했으며 회귀도 없었다. 특히 SVG 3장을 실제 구현에 맞춰 다시 그린 것은 **"자기 성과를 축소하던" 문제를 없앤** 의미 있는 개선이다. 기억 게임을 색 8→12개로 늘려 상한 문제를 푼 것도 방향이 맞다.

앞으로 남은 것은 **버그가 아니라 "완성도"**다. 코드는 이제 계획보다 5주 앞서 있는데, 정작 **회사와 교수가 보는 화면**에는 그게 드러나지 않는다 — 신규 계정으로 데모하면 성장도 재접속도 0으로 보이고, 효과 검증 데이터를 뽑을 도구도 없으며, "운영자가 내용을 바꿀 수 있다"를 증명할 문서도 없다.

**지금 필요한 건 기능 추가가 아니라 "보여주는 일"**이다. 위 1·2·4·6번은 전부 이미 있는 기능을 **남에게 보이게 만드는 작업**이고, 합쳐서 반나절이면 끝난다.
