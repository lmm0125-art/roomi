## 二、🔴 새로 발견한 문제 (3건)

### 1. 기억게임 기호가 8개뿐인데 색은 12개 → **7단계부터 기호가 중복된다**

```js
1764: const MEM_SHAPES = ['●','▲','■','◆','★','♥','▶','◀'];        // 8개
1766: mm.shapeOf = mm.colorOf.map((_, i)=>MEM_SHAPES[i % MEM_SHAPES.length]);   // ★ 모듈로 순환
```

`MEM_COLORS` 는 12개, 최대 11칸이 필요하다. `i % 8` 로 순환하므로:

| 단계 | 칸 수 | 배정되는 기호 | 문제 |
|---|---|---|---|
| 1~6 | 3~8 | `● ▲ ■ ◆ ★ ♥ ▶ ◀` | 전부 고유 ✅ |
| **7** | **9** | `● ▲ ■ ◆ ★ ♥ ▶ ◀ ●` | **● 중복** ❌ |
| **8** | **10** | `● ▲ ■ ◆ ★ ♥ ▶ ◀ ● ▲` | ● ▲ 중복 ❌ |
| **9** | **11** | `● ▲ ■ ◆ ★ ♥ ▶ ◀ ● ▲ ■` | 3종 중복 ❌ |

**난이도가 가장 높은 7~9단계에서, 색각이상 아동은 같은 기호 두 개를 구분할 수 없다.** 방금 만든 접근성 기능이 **정작 가장 필요한 구간에서 무력화**된다. (색으로 구분하는 일반 아동은 영향 없음 — 즉 이 기능의 대상자에게만 실패한다.)

**수정(3줄)**：`MEM_SHAPES` 를 12개 이상으로 늘리거나(`✚ ◇ ▣ ✦ ⬟ ⬢` 등 추가), `show` 를 `Math.min(MEM_COLORS.length, MEM_SHAPES.length, …)` 로 묶는다.

## 四、총평

이번 라운드는 **V5 제안을 정확히 이해하고 제대로 구현**했다. 특히 교환 가격을 "목표 부품 가격 비례"로 바꾼 설계는 **경제 논리를 정확히 복구**한 것이고(회수율 100%), 데모 계정도 `Lv.5 · 7일 · 재접속률 86%` 로 **발표에서 성장 스토리가 실제로 보이게** 만들었다. 관리자 API 와 CSV 는 W13 효과 검증의 인프라를 마련한 것으로, 앞선 라운드들보다 **한 수 위의 작업**이었다.

다만 이번에도 같은 패턴이 하나 남았다 — **"새로 만든 것의 경계값을 확인하지 않았다."**
- 기호 8개 vs 색 12개 → 7단계부터 중복 (난이도 최고 구간에서 접근성 기능이 꺼진다)
- 데모 버튼 → 매 클릭마다 정크 계정 1개 → 통계 평균이 절반으로

두 가지 모두 **정상 경로(1~6단계 / 1회 클릭)만 확인하면 안 보이고, 경계(7~9단계 / 반복 클릭)에서만 드러난다.** 앞선 라운드의 `(o.qty||1)`, `PAL_BASE`, `_starting` 과 정확히 같은 유형이다. **수정 후 "최대 난이도·최대 반복" 한 번씩만 눌러보는 습관**이 이 프로젝트에서 가장 효율이 높은 검증이다.

세 가지 수정(기호 추가·통계 필터·관리자 키)은 **합쳐서 20분**이면 끝나고, 그중 두 개는 **평가기준(个人信息 · 효과 검증 수치)** 에 직접 영향을 준다.
