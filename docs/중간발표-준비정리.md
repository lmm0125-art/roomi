## 0. 결론 먼저

> **중간발표는 우리에게 "위기"가 아니라 "기회"다.**
>
> 코드는 **이미 기말 수준**을 넘어섰다. 중간에 보여줄 것은 충분하고도 남는다.
> 그러니 중간은 **"더 많이 보여주는 자리"가 아니라 "방향을 확인받는 자리"** 로 쓰는 것이 이득이다.
>
> 특히 **공작소 탑재 형태**와 **연결점**은 회사 확인이 필요한데, 이걸 **중간발표 자리에서 직접 여쭙는 것**이
> 가장 빠르고 확실하다. (계획서가 스스로 정한 "W4 전 확인" 마감은 이미 지났다.)

### ⚠️ 먼저 확인해야 할 것

- [ ] 중간평가가 **점수에 반영되는 비율**

> 위 4가지는 문서로 알 수 없습니다. **이번 주에 확인**하세요.

## 2. 실행방안이 말하는 "중간" 요건

### 계획서에 명시된 것 (단 하나)
| 항목 | 원문 | 시기 |
|---|---|---|
| **조별평가지 / 동료평가지** | 조 간 상호평가 / 조원 간 상호평가 (10점 척도 + 근거) | **중간 · 기말** |

즉 **계획서가 중간에 요구하는 산출물은 두 가지 평가표**입니다.
별도의 "중간 보고서"나 "중간 발표 자료" 양식은 계획서에 없습니다.

### 15주 일정에서의 위치
계획서의 W6–7 은 **"골격을 세운다(로그인 · 라우팅 · 핵심 화면 1개)"** 구간입니다.
즉 **중간 시점에 요구되는 수준은 "골격이 서 있는 것"** 입니다.

### 회사가 요구한 "중간 확인"
> 「**중도에 확인받아라**」 — "이거 만들었는데 괜찮은지 확인해 주세요. **DOROBUS와 안 맞으면 좋은 점수를 줄 수 없다**"

계획서는 이를 **"W4 전에 연결점을 이현승 팀장에게 확인"** 으로 구체화했습니다.
**이미 약 2주 지났습니다.** 중간발표가 이 확인을 받을 마지막 자연스러운 자리입니다.

## 3. 중간발표에서 어디까지 해야 하는가

3단계로 정리했습니다.

| 수준 | 요구되는 것 | 우리 현재 상태 |
|---|---|---|
| **최소 (통과선)** | · 과제 이해를 보여주는 기획 요약<br>· 화면 설계 또는 목업<br>· "앞으로 이렇게 만들겠다" | ✅ **훨씬 상회** |
| **표준** | · **동작하는 프로토타입** (핵심 1개 기능)<br>· 사용 흐름 · 재화 흐름 정리<br>· 기업 요구 반영 내역 | ✅ **초과 달성** |
| **이상 (상위)** | · 위 전부 + **완성도 높은 데모**<br>· 효과 검증 **계획**<br>· 회사 확인 완료 | ⚠️ 데모·계획 ✅ / **회사 확인 ❌** |

### 판정
```
기획 · 설계 · 개발   →  이미 기말 수준 (18개 화면 기능, 관리자 API, 안전장치까지)
문서 산출물          →  기획서 · 사례조사 · 운영자가이드 · 효과검증 계획 완비
부족한 것            →  ① 회사 연결점 확인  ② 사용자 검증 데이터
```

> **중간까지 새로 만들 것은 없습니다.** 있는 것을 **정리해서 보여주고**, **확인받는 데** 집중하세요.

## 6. 중간용 발표 구성 (8~10장 권장)

기존 18장을 **그대로 다 쓰지 마세요.** 중간은 시간이 짧고, 핵심만 봅니다.

| # | 슬라이드 | 원본 |
|---|---|---|
| 1 | 표지 | 1 |
| 2 | 문제 정의 (수업 주 1회 · 재화 불균형) | 2 + 4 |
| 3 | **사례조사** ★필수 | 5 + 6 |
| 4 | 전략 + **기대효과** ★필수 | 7 + 8 |
| 5 | **사용 흐름** ★필수 | 9 |
| 6 | **재화 흐름** ★필수 | 11 |
| 7 | **연결점 + 확인 요청** ← 중간의 핵심 | 12 |
| 8 | 데모 (3분) | — |
| 9 | 앞으로의 계획 (검증 · 일정) | 16 + 17 |

> **7번이 중간발표의 목적입니다.** "이렇게 맞물리게 만들었는데, 이 방향이 맞습니까?"를
> 그 자리에서 여쭙고, **가능하면 그 자리에서 답을 받아 기록**하세요.

### 데모는 3분 → 2분으로 압축
```
리포트(20초) → 마이룸 3D + 성장(40초) → AI 과제 1개(20초) → 상점·주말한정(20초) → 자랑하기(20초)
```

## 8. 중간 → 기말 로드맵

```
[중간 W8]  데모 + 연결점 확인
              ↓
[W9–11]   사용자 테스트 5~10명 (초등 고학년~중학생)
          · 회사 피드백 반영
          · 공작소 탑재 형태 확정
              ↓
[W12]     내부 테스트 · 버그 수정
              ↓
[W13]     효과 검증 — 재접속률 · 체류시간 · 셀 사용량 · 과제 제출률 전후 비교
              ↓
[W14]     최종 발표 자료 + 리허설
              ↓
[W15]     최종 발표 + 조별평가지 · 동료평가지 · 성찰일지
```

### 기말까지 반드시 채워야 하는 빈칸
| 항목 | 왜 |
|---|---|
| **사용자 테스트 데이터** | 평가기준에 "검증 지표"가 명시. 지금은 0명 |
| **회사 확인 결과** | "실현 가능성"의 전제 |
| **HWP 양식 전부** | 제출 요건 |
| **팀활동보고서 주간 누적** | 중간·기말 평가 자료 |
