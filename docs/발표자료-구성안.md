## 4. 데모 시나리오 (3분)

> **평가기준 명시: "체험판 강사/학생 계정으로 실제로 시연할 수 있는가"**

### 사전 준비
- [ ] 브라우저 탭 2개 미리 열어 두기 (로컬 + 온라인 백업)
- [ ] **데모 계정 버튼**으로 7일치 성장 데이터가 있는 상태를 미리 만들어 둠
- [ ] 소리 켜둠 (효과음 확인용)
- [ ] 네트워크 불안 시를 대비해 **오프라인 실행본** 준비

### 진행 (3분)
```
[0:00] 시작 화면 → "체험용 프로토타입입니다. 로그인은 생략합니다."
        → 데모 계정 버튼 클릭 → 7일치 기록이 있는 리포트 먼저 보여주기

[0:20] 리포트 화면
        "이 아이는 7일 중 6일 접속했고, 평균 체류 22분, 셀은 500개 벌어 180개를 썼습니다."
        ★ 여기서 '재접속률'이라는 단어를 반드시 쓴다

[0:50] 마이룸 진입
        · 성장 배너(CH.2 멈춘 기계의 노래) — "이번 주 주제가 도로랜드 챕터와 연결됩니다"
        · 로봇이 자동으로 걸어다님 → 클릭하면 다가와 인사
        · 7칸 연속 방문 달력 → "내일 오면 +35셀이라고 미리 보여줍니다"

[1:30] 오늘의 과제
        · AI 과제 카드에 주제 표시 → 답변 작성 → 로봇이 반응
        · 셀이 늘어나는 순간 보상음 + 숫자 변화

[2:00] 미니게임
        · 반사 속도 1회 플레이 → 보상 확인
        · 랭킹 버튼 → "닉네임은 가려서 보여줍니다" (개인정보 배려 어필)

[2:30] 상점
        · 주말 한정 아이템 잠금 상태 → "주말에 열립니다 = 주말 재방문 이유"
        · 부품 구매 → 로봇에 즉시 반영 → 성장 외형 변화

[2:50] 자랑하기
        · 3D 화면을 그림으로 저장 → "부모님께 보여주는 출구"
```

### 데모 실패 대비
| 상황 | 대응 |
|---|---|
| 3D가 안 뜸 | 2D 폴백으로 자동 전환됨 (설명하며 진행) |
| 서버 응답 지연 | 온라인 백업 탭으로 전환 |
| 네트워크 완전 차단 | 로컬 실행본(`start.command`) |
| AI 대사가 안 나옴 | "AI가 응답하지 않으면 예비 대사로 자동 전환됩니다" — **이것 자체가 설계 설명** |

## 5. 예상 질문과 답변

| 예상 질문 | 답변 요지 |
|---|---|
| **"기존 DOROBUS에 그대로 넣을 수 있나?"** | 셀·상점·마이룸은 **기존 것을 그대로 씁니다.** 우리가 추가하는 것은 ① 셀 획득 경로(서버 로직) ② 상점 아이템 행 ③ 마이룸 오브젝트 배치입니다. 3D는 Babylon.js 7, 서버는 Node/Express로 **회사 스택과 동일 계열**입니다. |
| **"공작소에 어떻게 넣나?"** | 콘텐츠 모듈 단위로 분리되어 있어 공작소 진입점에서 호출하는 형태로 붙일 수 있습니다. **연결 방식은 확인받고 싶습니다.** |
| **"아이가 정말 다시 오나?"** | 사용자 테스트 결과 N명 기준 재접속률 X%. 다만 표본이 작아 방향성 확인입니다. |
| **"운영자가 내용을 바꿀 수 있나?"** | 네. 아이템·과제·주제·대사 **4종이 모두 DB 기반**이라 코드 수정 없이 추가·수정됩니다. 이번 주 주제는 관리자 API로 등록합니다. |
| **"AI 품질이 아이 수준에 맞나?"** | 4단계 모델 체인 → 백업 LLM → 18개 예비 대사로 **항상 응답을 보장**하고, 모든 출력에 안전 필터를 겁니다. |
| **"개인정보는?"** | 닉네임만 수집, 실명·연락처 없음. 계정 삭제 시 DB에서 실제 삭제. 랭킹은 닉네임을 마스킹합니다. |
| **"과몰입은?"** | 하루 40분 제한 + 보호자 승인 게이트. 체류시간 지표도 같은 40분 상한을 적용해 정책과 지표를 일치시켰습니다. |
| **"왜 마이룸을 새로 안 만들었나?"** | 마이룸은 이미 회사에 있습니다. **새로 만들면 이식성이 떨어집니다.** 기존 공간에 우리 오브젝트를 얹는 방식이 맞다고 판단했습니다. |
| **"타자 시즌은?"** | 회사에서 승인해 주신 사항으로 인지하고 있습니다. 현재는 반응·기억 2종을 먼저 완성했고, 시즌 구조는 `items.limited_days` 로 확장 가능하게 준비되어 있습니다. **(미구현 사실은 솔직히 인정)** |
| **"일회성으로 끝나지 않나?"** | 반복 구매 소비처(색칠 스킨)와 주말 한정·주간 주제 순환으로 지속성을 확보했습니다. |

## 6. 발표 자료 제작 체크리스트

내용:
- [ ] 4대 필수 페이지 포함 (사례조사·기대효과·사용흐름·재화흐름)
- [ ] 기대효과 3가지가 회사 표현과 일치
- [ ] **`셀` `재화 흐름` `체류` `재접속`** — 평가표 키워드를 정확히 사용
- [ ] 도면 3종 삽입 (사용흐름도·셀흐름도·와이어프레임)
- [ ] 실제 화면 캡처 포함
- [ ] 검증 수치 포함 (표본 한계 명시)

- [ ] 애니메이션 과다 사용 금지(발표장 PC 성능 차이)

- [ ] 10분 시간 재고 2회 이상 리허설

- [ ] 예상 질문 답변 소리 내어 연습

당일:
- [ ] 체험 계정 유효기간 확인 (**2026-12-25 만료 주의**)

## 7. 발표에서 강조할 3가지

1. **"수업이 없는 날"을 직접 겨냥했다** — 원래 문제를 정확히 다시 진술하고, 셀 획득처를 5개 늘린 것으로 답한다
2. **기존 자산을 새로 만들지 않았다** — 마이룸·상점·셀을 그대로 쓰고 연결점만 정의 → 이식성
3. **아이가 눈으로 느끼는 변화를 만들었다** — 로봇이 실제로 자라고, 내일 보상이 미리 보이고, 만든 것을 자랑할 수 있다
