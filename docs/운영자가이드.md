# 운영자 가이드 — 루미(RooMi) 콘텐츠 관리

> **★ 2026-10-12 추가 — 운영자 웹 페이지가 생겼습니다**
> 브라우저에서 **`/admin`** (예: https://my-dorobot.app.workbuddy.host/admin.html) 을 열고
> **ADMIN_KEY** 를 입력하세요. 할 수 있는 일:
> ① 지표 요약(평균 재접속률·체류·과제·로봇 수) ② 계정별 현황 표 + CSV 내보내기
> ③ 이번 주 주제 바꾸기(AI 과제 문제에 연결) ④ 전체 계정에 우편(공지·보상) 보내기 ⑤ 시연용 더미 계정 정리
>
> 아래 2장부터는 웹 페이지로 못 하는 **저빈도 작업(아이템·과제·대사 추가)** 의 SQL 조작법입니다.


> 대상: DOROBUS 운영 담당자 · 강사
> 목적: **코드를 수정하지 않고** 콘텐츠(아이템·과제·주제·대사)를 추가·수정한다
> 작성일: 2026-10-07

## 1. 왜 이 문서가 필요한가

평가기준에 다음 항목이 있습니다.

> 「**운영자가 문제·보상·아이템 등의 내용을 추가·수정할 수 있는가**」

본 프로토타입은 콘텐츠를 **DB 테이블 4개**로 분리해 두었습니다.
따라서 **프로그램을 고치지 않고도** 내용을 바꿀 수 있습니다. 이 문서는 그 방법을 정리한 것입니다.

---

## 2. 콘텐츠 4계층

| 대상 | 테이블 | 바꾸면 생기는 일 |
|---|---|---|
| **상점 아이템** | `items` | 상점 진열·가격·종류가 바뀐다 |
| **오늘의 과제** | `daily_quests` | 과제 종류·제목·보상이 바뀐다 |
| **이번 주 주제** | `weekly_topics` | AI 과제 질문의 주제가 바뀐다 |
| **로봇 대사** | `robot_lines` | LLM 실패 시 사용할 예비 대사가 바뀐다 |

> 그 외(성격 규칙 `COLOR_PERSONA`, 미니게임 난이도 상수)는 서버 코드 상수입니다.

## 3. 자주 하는 작업

### 3.1 이번 주 주제 바꾸기 ★ 가장 자주 쓸 기능

**관리자 API로 등록합니다.** (DB를 직접 만질 필요 없음)

```bash
curl -X POST \
  -H "X-Admin-Key: <ADMIN_KEY>" \
  -H "Content-Type: application/json" \
  -d '{"topic":"우리 동네 AI","keywords":"생활, 도움","chapter":3}' \
  https://<주소>/api/admin/topic
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `topic` | ✅ | 주제 이름 (최대 60자) |
| `keywords` | | 질문 생성에 참고할 키워드 (최대 80자) |
| `chapter` | | 도로랜드 챕터 번호 (기본 1) |
| `week` | | `YYYY-MM-DD` (해당 주의 **월요일**). 생략하면 **이번 주** |

**동작**
- 등록하면 그 주의 AI 과제 질문이 해당 주제로 생성됩니다
- **등록하지 않으면 도로랜드 챕터가 주차에 따라 자동 순환**하므로 방치해도 매주 질문이 달라집니다
- 같은 주에 다시 등록하면 **덮어씁니다**

**확인**
```bash
curl https://<주소>/api/public/stats          # 참고용 집계
curl -H "X-Admin-Key: <키>" https://<주소>/api/admin/stats
```

> ⚠️ `ADMIN_KEY` 환경변수가 설정되지 않으면 관리자 API는 **503을 반환**합니다(의도된 안전장치).
> 배포 시 반드시 키를 설정하세요.

### 3.2 새 아이템 추가하기

```sql
-- 예: 새 로봇 부품 추가
INSERT INTO items(name, type, price) VALUES ('무지개 날개', 'part', 150);

-- 예: 새 색칠 스킨 추가 (반복 구매 가능해야 하므로 consumable=1)
INSERT INTO items(name, type, price, consumable) VALUES ('하늘 스킨', 'skin', 40, 1);

-- 예: 주말에만 파는 한정 아이템 (0=일, 6=토)
INSERT INTO items(name, type, price, consumable, limited_days)
VALUES ('주말 한정 왕관', 'skin', 99, 1, '0,6');
```

| 컬럼 | 값 |
|---|---|
| `type` | `part`(로봇 부품) · `decor`(방 장식) · `skin`(색칠 스킨) · `shard`(부품 조각) |
| `price` | 셀 가격 |
| `consumable` | `1` = 반복 구매 가능, `0` = 1회만 |
| `limited_days` | `NULL` = 상시, `'0,6'` = 일·토만 |

**⚠️ 중요**: 새로 추가한 아이템은 **반드시 눈에 보이는 효과가 있어야 합니다.**
- `skin` → `public/app.js` 의 `SKIN_PALETTES` 에 **색 조합을 등록해야** 로봇 색이 바뀝니다
- `part` / `decor` → `app.js` 의 `buildOwnedDecors()` / `attachParts()` 에 **3D 생성 코드를 추가해야** 보입니다
- 등록하지 않으면 **"사도 아무것도 안 보이는" 아이템**이 됩니다 (실제로 있었던 문제)

**스킨 색 등록 예**
```js
const SKIN_PALETTES = {
  // ...
  '하늘 스킨': { body:'#5aa9e6', head:'#b8e0ff', antenna:'#ffc857', arms:'#3d7ea6', legs:'#2a5f80' },
};
```

### 3.3 오늘의 과제·보상 조정하기

과제는 **날짜별로 자동 생성**됩니다. 보상 기본값은 서버 상수입니다.

| 과제 | 기본 보상 | 위치 |
|---|---|---|
| 간식 주기 | 10 셀 | `ensureQuests()` |
| 칭찬하기 | 10 셀 | 〃 |
| AI 과제 | 30 셀 | 〃 |
| 반사 속도 | 10~50 셀 | `/api/game/result` |
| 기억 순서 | 50~110 셀 | 〃 |
| 연속 방문 | 10~100 셀 (7일 주기) · 28일 +200 | `STREAK_REWARDS` |

특정 날짜의 과제를 직접 바꾸려면:
```sql
UPDATE daily_quests SET reward = 20 WHERE quest_date = '2026-10-10' AND type = 'feed';
```

### 3.4 로봇 대사 추가하기

```sql
-- 성격 × 상황 조합으로 추가
-- personality: 활발이 / 차분이 / 반짝이 / 숲돌이 / 몽글이 / 멋돌이
-- situation  : greeting / feed / praise
INSERT INTO robot_lines(personality, situation, line)
VALUES ('활발이', 'feed', '우와! 오늘 간식은 특별히 맛있어!');
```
이 대사는 **LLM 이 응답하지 못할 때** 사용됩니다(예비 대사).

### 3.5 아이템 가격 조정

```sql
UPDATE items SET price = 50 WHERE name = '로켓 부스터';
```

**경제 균형 주의**: 하루 최대 획득은 약 140~240셀입니다.
전체 아이템 가격 합계가 이보다 너무 작으면 **며칠 만에 살 것이 없어집니다.**
→ **반복 구매 가능한 아이템(스킨)** 을 충분히 두는 것이 안전합니다.

## 4. 현황 조회

### 4.1 개인정보 없는 집계 (키 불필요 — 발표·보고서용)
```bash
curl https://<주소>/api/public/stats
```
```json
{"participants":13,"avgReturnRate":13,"avgPlayMinutes":81,"avgActiveDays":1,
 "avgQuests":0.3,"avgGames":0.3,"note":"개인 식별 정보는 포함하지 않는 집계값입니다"}
```
- 데모·시연·테스트 계정은 **자동 제외**됩니다
- **개인을 식별할 수 있는 값은 포함되지 않습니다**

### 4.2 개별 데이터 (관리자 키 필요)
```bash
curl -H "X-Admin-Key: <키>" https://<주소>/api/admin/stats        # 화면용 요약+목록
curl -H "X-Admin-Key: <키>" -o metrics.csv \
     https://<주소>/api/admin/export.csv                           # 엑셀용 CSV
```
CSV 컬럼 20개: `id, nickname, created_at, level, exp, streak, balance, activeDays,
spanDays, returnRate, playMin, playMinRaw, visits, quests, games, parts, earned, spent,
hasRobot, firstVisit`
- 엑셀에서 한글이 깨지지 않도록 **BOM 이 포함**되어 있습니다

### 4.3 개별 계정 삭제 (개인정보 보호)
앱 화면의 `🔄` 버튼 → 확인 → **서버 DB에서 실제 삭제**됩니다
(계정·로봇·인벤토리·거래내역·과제기록·접속기록 전부)

## 5. 지표 읽는 법

| 지표 | 정의 | 주의 |
|---|---|---|
| **재접속률** | `활동일수 ÷ 경과일수 × 100` | 매일 접속하면 100%. 가입 당일도 포함 |
| **체류시간** | 하루 **40분 상한**을 적용한 합계 | 정책(하루 40분 제한)과 일치시킨 값 |
| `playMinRaw` | 상한을 적용하지 않은 원값 | 탭을 켜 둔 시간이 섞일 수 있음 |
| **셀 사용량** | 상점 지출 합계 | `earned` 와 함께 보면 **사용률**을 알 수 있음 |

> **사용률 = spent ÷ earned**. 이 값이 낮으면 "벌기만 하고 쓸 곳이 없다"는 뜻이므로
> 소비처(아이템)를 늘려야 합니다.

## 6. 주의사항

1. **`ADMIN_KEY` 를 반드시 설정하세요.** 미설정 시 관리자 API가 503으로 막힙니다(안전장치).
   기본 키는 **없습니다** — 예전에 기본값이 있어 누구나 사용자 데이터를 내려받을 수 있었습니다.
2. **아이템을 추가하면 보이는지 반드시 확인하세요.** 색 조합·3D 생성 코드 등록을 빠뜨리면
   "돈만 내고 아무것도 안 보이는" 아이템이 됩니다.
3. **가격 조정 시 하루 획득량(140~240셀)을 기준으로** 판단하세요.
4. **주제를 등록하지 않아도** 도로랜드 챕터가 자동 순환합니다. 급할 때는 그대로 두어도 됩니다.
5. DB 파일은 **하나의 SQLite 파일**입니다. 정기적으로 백업하세요.
