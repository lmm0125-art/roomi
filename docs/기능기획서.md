# 기능 기획서 — 루미(RooMi)

> ㈜도로 × 한양대 ERICA IC-PBL 2026-2학기 · 인공지능학과
> 과제명: **아이들이 매일 다시 접속하고 싶은 DOROBUS 콘텐츠 개발**
> 대상: DOROBUS (dorobus.com) · 주 사용자: 초등 고학년 ~ 중학생
> 작성일: 2026-10-07 · 버전 1.0

---

## 1. 개요

### 1.1 한 줄 정의
> **아이가 직접 만든 로봇이 마이룸에 살면서, 매일 돌아올 이유를 만들어 주는 콘텐츠 모듈.**

### 1.2 범위
| 구분 | 내용 |
|---|---|
| 대상 사용자 | 초등 고학년 ~ 중학생 (DOROBUS 실제 사용자층) |
| 플랫폼 | Web (브라우저에서 바로 실행, 설치 없음) |
| 핵심 자산 | 로봇(아이가 색칠·명명) · 셀(플랫폼 재화) · 마이룸(3D 공간) |
| 개발 범위 | 독립 실행 가능한 콘텐츠 모듈 1개 + 기존 자산과의 연결점 |
| 제외 범위 | 로그인·회원·결제·수업 운영 (기존 DOROBUS 담당) |

### 1.3 왜 이 형태인가
- 회사 요청: **"DOROBUS 위에 만들 필요 없이, 콘텐츠만 주면 우리가 가져다 공작소에 넣겠다"** → **독립 실행 가능한 모듈**로 제작
- 회사 요청: **"로그인·진입 과정은 보지 않는다"** → 계정 체계는 닉네임 한 줄로 축약
- 회사가 꼽은 최우선: **공작소 또는 미니게임** → 두 요소를 모두 포함하되, **AI 콘텐츠는 공작소 성격**으로 구성

## 2. 배경과 문제 정의

### 2.1 As-Is (사실)
- DOROBUS의 가상 화폐 **셀(Cell)** 의 획득처는 **수업 · 과제 완료 · 타자게임 1등 · 이벤트**로 한정
- 반면 소비처는 풍부: 마이룸 꾸미기(가구·벽지·스킨·펫), 상점 가챠(장비·펫·스킨)
- **획득처 < 소비처** 구조

### 2.2 Pain Point
> DLS 온라인 수업은 **주 1회**. 수업이 없는 날에는 아이가 DOROBUS에 들어올 이유가 없다.
> 결과적으로 **접속 일수가 적다** — 이것이 기업이 제시한 원래 문제다.

### 2.3 To-Be (가설)
| # | 가설 | 검증 방법 |
|---|---|---|
| 1 | 아이가 **직접 만든 존재**가 마이룸에 살면, "내 로봇이 나를 기다린다"는 감정이 재접속 동기가 된다 | 재접속률 |
| 2 | 색칠 결과를 AI가 성격·대사로 바꾸면, "다른 색을 칠하면 다른 성격이 나온다"는 호기심으로 반복 플레이가 생긴다 | 로봇 재생성·색칠 횟수 |
| 3 | 매일 바뀌는 **오늘의 AI 과제**를 완료하면 셀을 받고, 그 셀로 부품을 사서 꾸미면 **획득처 확대 + 소비 촉진**이 동시에 일어난다 | 셀 사용량·과제 제출률 |

## 3. 탭 선택과 근거

DOROBUS 학생 화면은 `대시보드 / 내 수업 / 공작소 / 미니게임 / 마이룸` 5개 축으로 구성된다.

| 탭 | 채택 여부 | 이유 |
|---|---|---|
| **공작소** | ✅ **주 무대 (AI 콘텐츠)** | 회사가 "가장 원하는 부분"으로 명시. 만들기·창작 활동과 결이 맞다 |
| **미니게임** | ✅ **보조 (난이도 곡선)** | 회사가 함께 지목. 짧은 세션으로 매일 접속 이유를 만든다 |
| **마이룸** | ✅ **소비·전시 출구** | 결과물(로봇·부품)이 보이는 곳. **새로 만들지 않고 기존 공간을 활용** |
| 상점 | ✅ 연결점 | 기존 상점에 아이템을 **공급**하는 방식 (상점 자체는 기존 것 사용) |
| 대시보드/내 수업 | ⛔ 범위 밖 | 기존 DOROBUS 담당 |

> **설계 원칙: 기존 자산을 새로 만들지 않는다.**
> 마이룸·상점·셀은 DOROBUS에 이미 있다. 우리는 **그 안에 채워 넣을 콘텐츠와 재화 흐름**을 만든다.

## 4. 핵심 기능 정의

### 4.1 로봇 제작 (만들기)
| 항목 | 내용 |
|---|---|
| 목적 | 아이가 **소유감**을 느끼는 대상을 만든다 (가설 1의 출발점) |
| 동작 | ① 4종 템플릿 선택 → ② 12색 팔레트로 5개 부위(안테나·머리·몸통·팔·다리) 색칠 → ③ 이름 짓기 |
| 데이터 | `robots(template, palette, name, personality, greeting)` |
| 보상 | 완성 시 **+50셀 + 부품 1개** |

### 4.2 AI 성격·대사 생성
| 항목 | 내용 |
|---|---|
| 목적 | 색칠이라는 **단순 행동을 캐릭터성으로 번역**해 애착을 만든다 |
| 동작 | 색 조합 → 성격 6종 중 결정(규칙) → LLM이 인사말·소개 생성 |
| 품질 보장 | **4단계 Gemini 모델 체인 → DeepSeek 백업 → 18개 예비 대사** 로 항상 응답 보장 |
| 안전 | 모든 LLM 출력은 **금칙어·길이·링크 검사** 후 노출, 미통과 시 예비 대사로 대체 |
| 데이터 | `robot_lines(personality, situation, line)` — 운영자가 추가 가능 |

### 4.3 마이룸 생활 (3D)
| 항목 | 내용 |
|---|---|
| 목적 | 로봇이 **살아 있는 느낌**을 준다 |
| 동작 | Babylon.js 3D 방. 로봇이 대기 중 자동 산책, 클릭 시 다가와 대화, 점프·호흡·깜빡임 |
| 상호작용 | 🍪 간식 주기 · 💬 칭찬하기 (각 하루 5회, LLM이 상황 대사 생성) |
| 성장 표현 | **Lv 구간에 따라 로봇 외형이 실제로 변한다** — 아기(작고 눈 큼·안테나 짧음) → 청소년 → 성체(크고 안테나 김) |
| 폴백 | 3D 실패 시 2D SVG로 자동 강등 |

### 4.4 오늘의 AI 과제 ★ 핵심
| 항목 | 내용 |
|---|---|
| 목적 | **수업 없이도 셀을 얻는 경로**를 만든다 (Pain Point 직접 해결) |
| 동작 | 매일 주제에 맞는 질문 3개 생성 → 아이에게 1개 배정 → 답변 작성 → 로봇이 반응 |
| **주제 연결** | **이번 주 주제(도로랜드 챕터 또는 교사 지정 주제)** 를 프롬프트에 넣어, 수업·세계관과 이어지는 질문을 만든다 |
| 보상 | +30셀 (하루 1회) |
| 예비 동작 | LLM 실패 시에도 **주제별 예비 질문**으로 연결이 끊기지 않는다 |

### 4.5 미니게임 2종 (난이도 곡선)
| 게임 | 규칙 | 보상 | 난이도 |
|---|---|---|---|
| ⚡ 반사 속도 | 초록불에 최대한 빠르게 클릭 (3회 중 최고) | 10~50셀 (빠를수록↑) | 반응 속도 |
| 🧠 기억 순서 | 한 칸씩 차례로 빛나는 순서를 기억해 재현 (최대 9단계) | 50~110셀 (단계↑) | 기억력 |
- **보상 계산은 전부 서버** — 클라이언트 조작으로 셀을 늘릴 수 없다
- 하루 1회씩 (`game_logs` 유니크 제약)
- **접근성: 색 + 도형 이중 채널** — 색각이상 아동도 플레이 가능

### 4.6 상점과 부품
| 아이템 종류 | 예 | 성격 |
|---|---|---|
| 로봇 부품(part) | 나사 장식 60 · 안테나 리본 80 · 로켓 부스터 120 | 1회 보유. **보유 시 과제 보상 +2셀/개 (최대 +10)** |
| 방 장식(decor) | 별 스티커 40 · 선물 상자 100 | 1회 보유. 마이룸에 실제 3D로 배치 |
| 색칠 스킨(skin) | 파랑·핑크·민트·노랑·보라 30~45 | **반복 구매**. 로봇 색이 실제로 바뀐다 |
| 부품 조각(shard) | 20 | 재료. **3개 → 1부품 교환** (부품 가격 비례) |
| 주말 한정 | 보라·무지개 스킨 | **토·일요일에만 판매** — 주말 재방문 이유 |

### 4.7 성장과 재접속 장치
| 장치 | 내용 |
|---|---|
| 레벨 | 누적 경험치 → Lv. 선형 곡선(100×Lv)이라 아이가 이해하기 쉽다 |
| 성장 단계 | Lv 구간별 아기/청소년/성체 — **3D 외형이 실제로 변한다** |
| 연속 방문 | 🔥 7일 주기 순환 보상 (10/15/25/35/50/60/100셀), 28일 완주 시 +200셀 |
| 연속 방문 달력 | **7칸 달력으로 "내일 받을 보상"을 미리 보여준다** — 예고된 보상이 재방문을 만든다 |
| 랭킹 | 오늘의 미니게임 top 5 (닉네임 일부 마스킹) |
| 자랑하기 | 3D 화면을 그림으로 저장 — 부모님·친구에게 보여주는 출구 |

### 4.8 리포트 (효과 검증 화면)

## 5. 연결점 — 기존 자산과 어떻게 맞물리는가

> 회사가 "실현 가능성"의 정의로 제시한 항목: **기존 셀·상점·마이룸과의 연결점이 명확한가**

| 기존 자산 | 연결 방식 | 구현 상태 |
|---|---|---|
| **셀 (재화)** | 획득처를 **+5개** 추가(로봇 완성·AI 과제·미니게임 2종·연속 방문) / 소비처를 **+2종** 추가(부품·스킨) | ✅ |
| **상점** | 기존 상점에 **아이템을 공급**. `items` 테이블에 행을 추가하면 진열된다 | ✅ |
| **마이룸** | 새 공간을 만들지 않고 **기존 3D 공간을 사용**. 부품·장식을 실제 3D 오브젝트로 배치 | ✅ |
| **공작소** | 만들기·창작 활동 축에 **AI 콘텐츠 모듈**로 탑재 | ⚠️ 회사 확인 필요 |
| **수업(DLS)** | 이번 주 주제를 수업 내용과 연결해 AI 과제 생성 | ✅ (주제 입력 방식) |
| **학생 계정** | 모든 결과를 **학생 계정 단위**로 기록 (`users` / `cell_tx` / `quest_logs`) | ✅ |

## 6. 재화(셀) 흐름

```
[획득 EARN]                                   [소비 SPEND]
 · 회원 가입 보너스        +100                · 로봇 부품      60 / 80 / 120
 · 로봇 완성              +50                 · 방 장식        40 / 100
 · 오늘의 AI 과제         +30 (매일)           · 색칠 스킨      30 / 45 / 60 (반복)
 · 간식/칭찬 과제         +10 ×2 (매일)        · 부품 조각      20 (반복)
 · 미니게임 2종           +10~50 / +50~110
 · 연속 방문 보상          +10 ~ +100 (7일 주기)
 · 28일 완주             +200
 · 부품 보너스            +2/개 (최대 +10)
                    ↓                                 ↓
              ┌─────────────────────────────────────┐
              │   셀 지갑 (users.cell_balance)       │
              │   모든 거래는 cell_tx 에 기록        │
              └─────────────────────────────────────┘
                    ↓
              로봇·마이룸 꾸미기 → 자랑하기 → 다시 접속
```

**설계 의도**
- 획득처를 **"수업이 있는 날"에서 "매일"로** 옮긴다 → 수업 없는 날에도 접속 이유 발생
- 소비처를 **반복 구매 가능한 것(스킨)** 중심으로 확보 → 일회성 포화 방지
- 모든 거래에 **출처(source)를 남겨** 재화 흐름을 추적 가능하게 한다

## 7. 운영자 콘텐츠 관리

> 평가기준 "**운영자가 문제·보상·아이템을 추가/수정할 수 있는가**"에 대한 답.

| 대상 | 저장 위치 | 변경 방법 |
|---|---|---|
| 상점 아이템 (이름·가격·종류) | `items` 테이블 | 행 추가/수정 (코드 수정 불필요) |
| 오늘의 과제·보상 | `daily_quests` 테이블 | 날짜별 행. 보상 값 조정 가능 |
| **이번 주 주제** | `weekly_topics` 테이블 | **관리자 API로 등록** (아래) |
| 로봇 대사 | `robot_lines` 테이블 | 성격 × 상황별로 행 추가 |
| 성격 규칙 | `COLOR_PERSONA` 매핑 | 색 → 성격 (서버 상수) |

**주제 등록 예시**
```bash
curl -X POST -H "X-Admin-Key: <키>" -H "Content-Type: application/json" \
     -d '{"topic":"우리 동네 AI","keywords":"생활, 도움","chapter":3}' \
     https://<주소>/api/admin/topic
```
주제를 등록하지 않으면 **도로랜드 챕터가 주차에 따라 자동 순환**하므로 방치해도 매주 질문이 달라진다.

**현황 조회**
- `GET /api/admin/stats?key=<키>` — 계정별 지표 + 요약
- `GET /api/admin/export.csv?key=<키>` — 전체 CSV (엑셀용 BOM 포함)
- `GET /api/public/stats` — 개인정보 없는 집계값 (키 불필요)

## 8. 안전 · 개인정보 · 시간 관리

> 평가기준 "초등~중학생의 **안전·개인정보·과몰입 방지**를 고려했는가"

| 항목 | 구현 |
|---|---|
| **콘텐츠 안전** | 모든 LLM 출력에 금칙어·길이·링크 검사. 미통과 시 예비 대사로 대체 |
| **개인정보** | 닉네임만 수집(실명·연락처 없음). **계정 삭제 기능 제공**(서버 DB에서 실제 삭제) |
| **랭킹 노출** | 다른 아이 닉네임은 **첫 글자만 표시**(`민준이` → `민○○`) |
| **관리자 데이터** | 관리자 키 미설정 시 **아예 동작하지 않음**(fail-closed). 기본 키 없음 |
| **과몰입 방지** | 하루 **40분 초과 시 잠금**, 보호자 승인 시에만 추가 허용 |
| **보호자 확인** | 곱셈 문제 게이트(서명된 토큰으로 정답 위조 불가) |
| **입력 검증** | 상황 화이트리스트 · 색상 형식 검증 · 길이 제한 · 에러 시 내부 정보 비노출 |

| 하지 않은 것 | 이유 |
|---|---|
| 로그인·회원·결제 | 회사가 "보지 않는다"고 명시 |

## 11. 확장 계획 (회차 · 시즌 · 난이도)

평가기준 "회차·시즌·난이도로 확장 가능한가"에 대한 답:

| 축 | 확장 방법 | 이미 준비된 것 |
|---|---|---|
| **회차** | `weekly_topics` 에 주차별 주제를 미리 등록 → 학기 단위 커리큘럼 | 주제 자동 순환 로직 |
| **시즌** | `items.limited_days` 로 기간 한정 아이템 (현재 주말 한정) → 계절·기념일 | 한정 판매 구조 |
| **난이도** | 미니게임 단계 상한·보상 곡선이 상수로 분리 | `MEM_MAX_LEVEL` 등 |
| **세계관** | 도로랜드 챕터(CH.1~5)를 주제로 사용 중 → 챕터 추가 시 그대로 확장 | `DEFAULT_TOPICS` |
