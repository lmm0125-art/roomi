### `ReferenceError: PAL_BASE is not defined` → 3D 마이룸이 죽었다

**원인**
`PAL_BASE` 는 **`robotSVG()` 함수 안**(L26)에 선언된 **함수 지역 변수**인데, 이번에 `effectiveColors()` 안의 두 번째 정의를 지우면서 바깥 함수에서 그 지역 변수를 참조하게 됐다.

```js
// L24  function robotSVG(template, pal){
// L26    const PAL_BASE = { doro:{...}, roundy:{...}, ... };   ← robotSVG 범위(L24~104) 안

// L441 function effectiveColors(template, palette){
// L442   // ★ V3 수정: PAL_BASE / DEFAULT_PAL 의 두 번째 정의를 제거했다.
// L443   //   파일 상단(L26/L18)이 유일한 진실 공급원이며, ...
// L445   const base = Object.assign({}, DEFAULT_PAL, PAL_BASE[template]||{}, palette||{});
//                                                        ^^^^^^^^^ 여기서 보이지 않는다
```

주석은 "파일 상단(L26/L18)이 유일한 진실 공급원"이라고 적고 있지만, **L26 은 파일 상단이 아니라 `robotSVG` 함수 내부**다. (`DEFAULT_PAL` 은 L18 로 진짜 모듈 레벨이라 정상 — 그래서 그쪽은 문제가 없다.)

**실행으로 증명**（파일에서 `effectiveColors` 소스를 그대로 추출해 호출）

## 五、총평

수정 자체는 **정확했다** — 지적한 4건은 추측 없이 그대로 반영됐고, 실측에서 모두 통과했으며, 회귀도 없었다. 특히 `AND v.qty>0` + `a+o.qty` 조합과 `_starting:true` 유지처럼 **원인을 정확히 짚은 수정**이었다.

문제는 단 하나, `DEFAULT_PAL`/`PAL_BASE` 단일화다. **중복을 없애려다 스코프를 확인하지 않았다.** 주석에 "L26이 파일 상단"이라고 적어둔 것이 그 착각의 증거다 — L26은 함수 안이다. 이 한 건이 3D 마이룸·상점 미리보기·로봇 재빌드를 동시에 죽였고, 하필 **온라인 데모에 이미 배포됐다.**

이번에도 같은 패턴이 반복됐다: **수정 후 실제로 화면을 열어보지 않으면 알 수 없는 종류의 오류**. `effectiveColors` 는 `node --check`(문법)로도, 서버 API 테스트로도 안 잡힌다 — 브라우저에서 마이룸을 한 번 열어보면 즉시 보인다. 앞으로 3D 관련 수정 뒤에는 **"마이룸에 들어가 3D 방이 뜨는지" 한 번만 확인**하는 것을 규칙으로 삼으면 이 부류는 전부 걸러진다.
